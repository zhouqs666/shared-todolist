# 2026-11-25：复看卡在真机上一直闪 —— 三个「本该不生效」的缺陷叠成合成器超预算

**关联规则**：AGENTS.md 铁律二（交付前必须全面测试，硬限制要列明）/ 铁律六（维度 E 性能、维度 F 测试）
**影响**：Android 真机（OPPO / ColorOS）打开图鉴复看卡后，卡片持续闪屏；epic/legendary 的金箔流光与全部粒子特效在生产环境从未显示过。Web / 桌面不受影响。

## 事故

业主在真机上点「头像左侧的图鉴入口 → 怦然心动 → 任意一张已开启的贴纸」，复看卡弹出后
**卡片本身一直在闪**（不是整屏黑场）。业主提供了 20 秒录屏。

从录屏里逐帧取像素（Chrome `requestVideoFrameCallback` 按呈现帧解码）复现并抓到了现场：

| 时刻 | 卡片区域亮区 | 画面 |
|---|---|---|
| 11.33s | 完整 | 正常 |
| **11.37s** | **下半截塌掉（亮区从 962px 缩到 594px）** | **残缺瓦片：文字重影、左侧彩色扫描条纹** |
| 11.40s | 完整 | 正常（30ms 后自愈） |
| **17.20s** | 同上 | **下半截整块变成紫色平板，文字与纸纹全部丢失** |
| 17.23s | 完整 | 正常 |

坏帧里**缺失的恰好是文字（网络字形）与纸纹，留下的正是纯 CSS/SVG 部分** —— 这是
**Android GPU 合成器输出不完整 Tile** 的典型形状，不是业务逻辑问题。

## 根因（三条独立缺陷叠成一条链）

### ① 画布在遮罩 `display:none` 时测量 ⇒ 退化成 1×1 像素

`reveal-card.js` 的 `runPlay()` 原本是：

```js
fillCard(spec);            // 这里把 overlay 置为 class="hidden" → display:none !important
fdpr = sizeCanvas(ui.fx);  // ← 此刻量尺寸：getBoundingClientRect() 全是 0
sizeHolo();
...
ui.overlay.classList.remove('hidden');   // ← 遮罩在这之后才可见
```

`sizeCanvas()` 里 `c.width = Math.max(1, r.width * dpr)` ⇒ **1×1**。
后果：`#rvHolo`（WebGL 全息层）变成「1 个着色器像素拉满整张卡」，`mix-blend-mode:screen`
把它叠成一层均匀色纱 —— **epic/legendary 的金箔流光从未真正渲染过**。

`#rvFx`（粒子层）更彻底：canvas 是**替换元素**，绝对定位 + `inset:0` 并不会拉伸它
（替换元素 `width:auto` 取内在尺寸，`left/right` 同时为 0 时按 CSS 2.1 §10.3.8 忽略 `right`）
⇒ 它的 CSS 尺寸永远是 1×1，**粒子 / 星芒 / 渗出 / 爆发在生产环境一次都没显示过**。

### ② 陀螺仪噪声 ⇒ 3D 子树每帧强制重栅格化 47 次/秒

`applyTilt()` 每帧无条件写两处 style：

```js
ui.tiltWrap.style.transform = `rotateX(...) rotateY(...)`;
ui.card3d.style.setProperty('--gx', `${50 + curTilt.x * 30}%`);
```

- `--gx` **从不生效**：`.f-body::after` 的 `background-position: var(--gx) 0` 被
  `rv-cardSheen` 动画整个覆盖（CSS 动画优先级高于普通声明）。实测把 `--gx` 改成 5% 后
  计算值仍是 `-60% 0px` —— 每帧让整棵卡片子树样式失效一次，换来零效果。
- `transform` 每帧都变 ⇒ 整棵 3D 卡片子树（`transform-style:preserve-3d` +
  `mix-blend-mode` 层 + 渐变文字 + SVG 滤镜）被强制**重新栅格化**。真机有陀螺仪，
  传感器噪声让 `curTilt` 每帧都动。

**受控实验（桌面注入 60Hz 噪声模拟真机）**：

| 场景 | `#rvTiltWrap` / `#rvCard3d` 的 style 变更 |
|---|---|
| 桌面（无陀螺仪） | **0 次 / 3 秒** |
| 注入 60Hz 传感器噪声 | **142 次 / 3 秒 ≈ 47 次/秒** |

这解释了「为什么我本地怎么测都复现不出来」：**桌面根本没有陀螺仪事件**。

### ③ 每帧重绘全息层 / 粒子层（未降频）

全息层每帧一次纹理上传、粒子层每帧一次全屏 clear，叠加在②之上把合成器预算打爆。

### 为什么「最近才出现」

版本时间线（只读查 `app_versions`）：

| 版本 | 发布 | 内容 |
|---|---|---|
| 3.5.0 | 10-05 | 开出卡片上线 |
| 3.6.0 | 10-06 | **图鉴复看入口上线**（闪屏的载体） |
| 3.7.0 | **10-14** | **霞鹜文楷 web font 落地 —— 全 App 正文换上网络字体** |
| 3.7.3 | 10-29 | 当前线上版本 |

把 3.6.0 之后每一个碰过「卡片渲染路径」的提交逐个 diff 过：**真正改变卡片文字渲染的只有
`81c4080`（即 3.7.0 的 web font）**。它把 `.f-name`（`background-clip:text` +
`color:transparent` 的渐变文字）、`.f-flavor`、`.f-meta` 从系统字体换成 1.6MB 网络字体 ——
Android WebView 上网络字形要按需栅格化进字形图集并上传纹理；系统字体则在系统缓存里，
重绘不涉及上传。**于是「每帧重栅格」从「贵但完整」变成「贵且可能撕裂」**，坏帧里缺失的
正是网络字形。

该提交自己写着：**「未验证：Android WebView 真机渲染（需发布后设备侧冒烟确认）」** ——
它是那批改动里唯一没在真机上验过的。

无法从仓库排除的外部变量：手机 **System WebView / ColorOS 更新**会改变 GPU 合成行为
（Android 上「突然出现」的经典诱因）；以及业主何时升到 3.7.x。

## 为什么既有测试体系没拦住（两个盲区叠加）

1. **E2E 默认走降级通道**：`e2e_common.login()` 统一写 `__e2e_fx_off=1` ⇒
   `toIdle(true)` + `no-anim` ⇒ **没有淡入、没有逐帧重绘、关闭时立即隐藏**，
   闪屏的三个条件一个都不成立。全量跑批永远看不到。
2. **断言只看 DOM 文字，不看画面**：`reveal_card_snapshot()` 读的是 `textContent` 与
   `getComputedStyle` 的 opacity —— 画布尺寸、纹理上传、Tile 完整性**全都在断言之外**。

## 修复与防回归

- **画布尺寸**：`runPlay()` 里把 `sizeCanvas(ui.fx)` / `sizeHolo()` 移到
  `ui.overlay.classList.remove('hidden')` **之后**（`getBoundingClientRect()` 会强制同步
  布局，遮罩可见后量到的就是真实尺寸）；`#rvFx` 补 `width:100%; height:100%`。
  实测：`#rvHolo` 1×1 → **554×775**（= 卡片尺寸 × dpr），`#rvFx` 1×1 → **780×1688**（= 视口 × dpr）。
- **掐断强制重栅格**：删掉从不生效的 `--gx` 写入；`transform` 仅在倾斜变化 > 0.02
  （约 0.22°，高于传感器噪声量级）时才写。
  实测：注入 60Hz 噪声下 style 变更 **142 次/3 秒 → 0 次/3 秒**。
- **降频**：idle 态重绘降到 ~30fps（`DRAW_INTERVAL_MS`），粒子物理按真实时间累积 dt，
  不会变慢。
- **防回归断言**（`scripts/test_blindbox.py` 7.1d / 7.5a）：epic 卡的 `#rvHolo` backing store
  必须覆盖卡片尺寸；`#rvFx` CSS 尺寸必须覆盖全屏；注入 60Hz 陀螺仪噪声 3 秒内
  `#rvTiltWrap`/`#rvCard3d` 的 style 变更 **≤ 5 次**。任一条退回旧实现即红。

## 第二版：真机确认后的残留（右下角每隔几秒闪一下）

3.7.4 发布后业主反馈：**主体闪烁消失**（原先闪的是一大片），但**史诗/传说款右下角仍会闪，
稀有款没有**。第二版定位到两处**同一类**问题（都是「3D 变换与纹理/着色器的耦合」）：

1. **画布按「投影尺寸」分配**：`sizeCanvas()` 用 `getBoundingClientRect()`，而卡片在 3D 里
   （perspective + rotateX/rotateY）→ 返回的是**投影后**的盒子，倾斜一变就变
   （实测布局 289×404 → 投影 288.6×404 → 倾斜后 282.3×408.3）。后果：① 分辨率欠 4%
   （554×775，应为 578×808）；② 倾斜一变纹理就被重新缩放采样 ⇒ 流光图案相对卡片漂移，
   **越靠卡片四角越明显**（透视畸变梯度最陡）。
   ⇒ 改用 `offsetWidth/offsetHeight`（**布局**尺寸，不受 transform 影响）。
2. **shader 与 DOM 变换脱节**（**上一版修复的副作用**）：上一版只把 DOM 变换量化成
   「跨阈值才写」，而 shader 仍在吃**连续变化**的 `curTilt` ⇒ 流光图案（`u_tilt`）持续
   相对卡片漂移，而卡片本身是跳变的 ⇒ 每次阈值被跨越，图案被「啪」地拽回去。
   ⇒ 引入 `appliedTilt`：**DOM 变换与 shader 共用同一份值**，两者永远一致。
   （稀有款没有 `#rvHolo`、没有 `u_tilt` ⇒ 完全不受影响 —— 与业主报告一致。）

第二版防回归断言（`scripts/test_blindbox.py` 7.5b / 7.5c）：
- `#rvHolo` 的 backing store == 卡片**布局**尺寸 × dpr（退回按投影尺寸量即红）；
- `getTiltDebug().shader`（shader 实际用的 `u_tilt`）== `getTiltDebug().applied`
  （DOM 变换用的那份）—— 这条不变量就是「不脱节」的机器判据。

> 教训补一条：**只把一半的量「量化」会造成新的不一致**。上一版为了省重栅格把 DOM 变换
> 量化了，却忘了 shader 还在用连续值 —— 两个消费者读到不同的真相，症状从「大面积闪」
> 变成「角落里闪」，很容易被当成新问题重新查一轮。**改动一个共享量的消费方式时，
> 要把所有消费者列出来一起改。**

## 第三版：真机确认「环境差异」后，定位到 glint 闪点（3.7.6）

业主反馈（关键三条）：

1. **切换到测试环境完全不闪**，而此时测试库的数据已被我改成与生产**完全同构**
   （12 张 v1 贴纸 / 96 条未删待办 / 1 条心里话 / 2 个账号）⇒ **触发条件不在数据**。
2. **断网（飞行模式）也闪** ⇒ 不是网络 / Realtime 驱动（推翻了我上一轮的假设）。
3. **闪的频率和时机有规律，好像总是在画面颜色变深的一瞬间闪**。

### 定位

把「只史诗/传说闪」这条当硬约束反推：史诗/传说**唯一**多出来的元素是 `#rvHolo`
（WebGL 全息层，稀有款是 `display:none`）。而它的着色器里正好有两个周期成分：

```glsl
float band = sin(... + u_time*0.55);                              // 11.4s 周期 → 全息层亮度脉动
float sp   = hash(floor(gp) + floor(u_time*7.0)*0.371);            // 7Hz 重排
col += u_glint * step(0.9915, sp) * 0.9;                          // 与底色无关的加色火花
```

**⇒ 底色被 `band` 压暗的瞬间，`glint` 的白火花是「加色」的、对比度最大 ⇒ 就是在那一刻
突兀地闪出来**（业主原话「画面颜色变深的一瞬间闪」）；**稀有款没有 `u_glint` ⇒ 天生不闪**。
64×90 网格里 ~49 个小火花、7 次/秒重排 —— 在 DPR 3 的手机上每个火花 ~13×14 设备像素，
是货真价实的频闪。

### 修复（3.7.6）

- 闪点频率 **7Hz → 1.4Hz**（金粉缓慢明灭，不再频闪）
- 幅度 **0.9 → 0.30**
- **与底色亮度联动**：`col += u_glint * step(0.9915, sp) * 0.30 * (0.25 + 0.75*baseLum)`
  ⇒ **底色暗时火花自动收敛**，直接消掉「变深的一瞬间闪」

### 这次为什么无法在本地验证

- 伪影本身是 **GPU 合成器的 Tile 级伪影**，桌面 Chromium（软件/桌面 GPU）不产生 ⇒ 桌面端
  量到的卡片右下角 σ=0.30（**整卡里最稳的地方**）⇒ 真机那下不是内容变亮变暗。
- 桌面端采样率 ~15–19fps，而火花是**稀疏**的（0.85% 的网格格），小采样区抓不到 ⇒
  前后频谱测不出 7Hz 成分。**本地只能验证「着色器能编译、全息层仍在渲染」，闪烁本身
  只能由真机判定。**
- 模拟器是 SwiftShader 软件渲染（1.1fps、`screenrecord` 0.7fps）⇒ 抓不到 1 帧伪影。

> 教训补一条：**「某个组件是某类现象的唯一共有物」是极强的定位约束**。
> 「稀有款不闪 + 史诗传说闪」直接锁死到 `#rvHolo`，比逐个排查合成链快得多。
> 而**现象的触发时刻（颜色变深的一瞬）往往直接对应机制**（加色火花遇暗底）。
> 另：本地复现不出来时，**先找「唯一共有物」再谈机制**，别在通用链路上反复猜。

## 第四版：真正的元凶 —— 集齐纪念卡留下的全屏画布（3.7.7）

3.7.6 之后业主仍反馈「还闪」，并附上一条关键信息：**「生产环境的集齐卡片庆祝又出现了一次」**。

### 链条

1. **canvas-confetti 用的是模块级全局画布**：第一次调用时 append 到 `document.body`，
   之后**永远不会自己移除**（只有显式 `confetti.reset()` 才 `removeChild`）。
2. 纪念卡的彩带参数是 `{ ..., zIndex: 1200 }`，且有一束从 **`origin:{x:0.85,y:0.7}`
   = 屏幕右下角**射出 ⇒ 画布是**全屏**的、**z-index 与复看卡遮罩 `#rvOverlay` 同级**、
   且在 DOM 里排在 `#rvOverlay` **之后** ⇒ **正好压在复看卡之上**，残影落在**右下角**。
3. 合成器要在「3D + `mix-blend-mode` 的卡片」与「一块全屏画布」之间混合 ⇒ **右下角的
   Tile 碎掉** ⇒ 用户看到的「史诗/传说款右下角每隔几秒闪一下」。**稀有款没有 `#rvHolo`
   （`display:none`，无混合模式）⇒ 这层重叠对它无害 ⇒ 稀有款不闪** —— 完全吻合。

### 为什么「只有生产环境闪」/「最近两天才出现」

- **切测试环境会 `location.reload()`**（`env-switch.js:128`）⇒ 整页重载把残留全清掉 ⇒
  测试环境永远干净（与数据无关 —— 我把测试库改成生产同构后依然不闪，正好印证）。
- **热更（bundle 切换）时 localStorage 不共享**（`update.js` 明确说明）⇒ 「已集齐庆祝」
  标记丢失 ⇒ **每次热更后第一次开图鉴都重播纪念卡** ⇒ 每次都重新埋雷。
  用户手机那天热更 → 从此开始闪；**我今天发的 3.7.4/3.7.5/3.7.6 又各触发了一次**
  ⇒ 业主看到「庆祝又出现了一次」。

### 修复（3.7.7）

- `hideMemorialCard()` 里调用 `confetti.reset()` ⇒ 移除那块全局全屏画布。
- `.memorial-card.hidden` 时把 scrim 的 `backdrop-filter` 摘掉（淡出过渡保留）。
- 修在「播完就清理」而不是「别重播」：**每次热更都会重播，重播必须无残留**。

验证：纪念卡播放中 → 全屏 canvas 1 个 / scrim `blur(3px)`；关闭后 → **0 个 / `none`** ✔

### 三轮定位的教训

- **「只有生产环境有问题」是个强线索，但不是数据**：先把两库做成同构再测，一次就把数据
  排除掉了 ⇒ 剩下的只有「这个 session 跑过什么」。
- **「某个仪式重播了」也是状态**：localStorage 随 bundle 切换丢失 ⇒ 每次热更都会重播
  纪念卡 ⇒ 而纪念卡留下了永久的合成负担。**「什么时候开始的」要同时看代码变更和
  设备侧事件（热更），不能只看代码。**
- **canvas-confetti 的全局画布是隐形残留**：它不会报错、不会显示异常、只在合成器层面
  添负担 —— 这类「第三方库留的全局资源」值得单独查一遍。

## 第五版（流程教训）：「发版」≠「用户已生效」

3.7.6（14:06 发布）与 3.7.7（14:36 发布）发布后，业主在 **14:13 / 14:40** 两次反馈
「还闪」。**那两次很可能都跑在旧 bundle 上** —— 热更链路是「打开 App → 后台下载 →
**再启动一次**才切换 bundle」，4~7 分钟根本来不及下载+重启完。

**⇒ 我把「还闪」当成了「修复无效」，据此又发了两版（3.7.6 glint、3.7.7 纪念卡清理），
把「已证伪」写进了复盘 —— 而它们其实很可能从未被测到。**

**判据（以后每轮都用）**：
1. **发版时间 vs 用户反馈时间**：间隔 < 30 分钟 ⇒ 必然未生效，先让他走完整热更循环。
2. **设备端是否真的切了 bundle**：判据是**「更新完成」欢迎动画是否出现**（它只在**新 bundle
   第一次打开**时播，右下角带 `No.X` 印记）。出现 = 已在最新 bundle；没出现 = 还是旧的。
3. `verify-release.mjs` 回读只证明**服务端有这版**，**不证明设备在跑这版** —— 这两件事
   必须分开说。

**⇒ 补一条产品改进（待做）**：更新面板里显示**当前 bundle 版本号**（`getCurrentBundleInfo()`
   已经能拿到），让「设备在跑哪版」一眼可见，不必再靠时序推断。

## 第六版（2026-11-25 15:20 录屏）：伪影本体抓到了 —— 是 GPU 合成器吐出的垃圾 Tile

业主 15:20 送来第二段录屏（19.5s / 576×1280 / **30fps CFR**）。这次不用 seek 抽样，
改用 **播放态 `requestVideoFrameCallback` 逐呈现帧**扫完全部 525 帧 —— 播放中 rVFC 给的
是解码器真正呈现的帧，不会有 seek 假帧，也不会漏帧。

> 踩坑记录：**暂停状态下 seek 后 rVFC 不触发**（回调数 0），必须 `play()` 才有帧。
> 这就是上一轮脚本卡死 12 分钟的原因，不是「解码慢」。

### 伪影本体

| 指标 | 实测 |
|---|---|

### 为什么之前五版都没修好

3.7.4/3.7.5（画布尺寸）、3.7.6（glint 频率）、3.7.7（纪念卡画布）**没有一项触及下面这
5 条强制 GPU 合成路径** —— 即使它们都已生效，闪屏也不会消失。

### 真正的病根：复看卡打开时同时存在 5 条 GPU 合成路径

1. **`#rvFx` 粒子层 = 全屏 canvas**，`stepParts()` 每 33ms 对整块 `clearRect` ——
   真机 2160×4800 ≈ **41.5 MB/帧 × 30fps ≈ 1.2 GB/s** 的清屏写入，**哪怕一个粒子都没有**。
2. **`.sticker-modal` 全屏 `backdrop-filter: blur(2px)`** → 合成器为它建 backdrop root 并全屏模糊。
3. **`#rvHolo` WebGL 层**每 33ms 重绘 + 纹理上传 + `mix-blend-mode: screen`。
4. **`#rvBeam` 全屏 `mask-image`** → 强制离屏渲染 pass。
5. **`.f-body::after`** `mix-blend-mode: screen` + 5s 动画 → 每帧重新栅格化。

外加 `#rvCard3d`/`#rvTiltWrap` 的 `will-change: transform` + `preserve-3d` 独立合成层。

**这条路径只在真机 GPU 上走**：模拟器是 SwiftShader 软件渲染（没有这条路径），桌面 GPU
足够强 ⇒ 两者都复现不了。**⇒ 所有「桌面/模拟器能跑通」的结论都不能否定真机现象。**

## 教训

1. **`display:none` 时量尺寸 = 量到 0**。任何「先量尺寸再显示」或「先显示再量尺寸」的顺序
   都要写进代码注释 —— 这个 bug 潜伏了 7 周（3.5.0 上线 → 3.7.4 修复）。
2. **替换元素不会被 `inset:0` 拉伸**。canvas / video / img 这类元素要显式写
   `width/height:100%`，否则永远是内在尺寸。
3. **每帧写 style 是要付栅格化代价的**，哪怕写的是一个「反正会被动画覆盖」的变量。
   传感器噪声级别的抖动不配触发重栅格化。
4. **降级通道会遮蔽一整类缺陷**。`__e2e_fx_off=1` 让 E2E 跑得又快又稳，代价是
   「特效路径」上的缺陷零覆盖 —— 需要断言这些路径时，**在用例里显式打开特效**。
5. **网络字体 + `background-clip:text` + 3D 变换 + 混合模式** 这四件套叠在一起，
   在 Android 上是渲染事故的高发组合；上线前没有真机验证，等于把雷留给用户。
6. **先量「伪影本体」，再谈修复**。前三轮都在猜「是什么在闪」，第四轮才拿到逐帧数据；
   第五轮才发现连测帧方法本身有坑（暂停 seek 不触发 rVFC）。**测量方法要先自证**：
   先用一帧已知有问题的素材验证「我的方法能抓到它」。
7. **「桌面试过了」不等于真机没问题**。本案的伪影只在真机 GPU 的合成路径上出现 ——
   模拟器是软件渲染、桌面 GPU 够强，两个环境都天然测不到。**凡是依赖 GPU 合成的特效，
   必须留一条真机验证通道，不能用 CI 绿灯代替。**
8. **每帧「无意义的全屏操作」比看起来贵的多**。粒子层每帧 `clearRect` 全屏（41.5MB/帧）
   在代码里只是一行，但它把一条全屏合成路径强行点亮了 —— **审查动画代码时，
   要问「这一帧我改动了整个屏幕的哪几个像素」。**
9. **「我改的那几行」不等于「根因」**。同一次事故里连发五版修复，每一版都建立在上一个
   **未证伪的归因**上；真机在第三版之后照闪不误，说明归因从一开始就不成立。
   ⇒ 每版改完先问「若这是根因，真机现象应当消失」，没消失就立刻停手、把结论改掉。
10. **回滚也要先核对「上一个版本有没有同样的问题」**。本次回滚到的 3.7.3 **本身就是闪的**
    （业主当天第一段录屏跑的就是它）⇒ 回滚只是「撤掉改动」，不是「止血」。
    这件事应该在发第一版之前就核对。
