## 🔴 P0 — 体验硬伤（建议优先解决）

### 1. 列表无组织，长清单淹没"今日要做的事"
**现状**：38 条平铺，按 `completed ASC, created_at DESC` 排序，未完成堆在最前面但只有 1 条；剩下 37 条划线已完成的"历史"塞满整屏。
**为什么痛**：双人情侣待办的核心场景是"我们今天/最近要一起做什么"，不是"我们过去做过什么"。当前默认视图让用户每次都得在历史里跋涉。
**建议**：
- **默认收起已完成**：已完成区域折叠成"已完成 N 条 ▾"，默认 collapsed；点开才展开。展开态可记忆（localStorage）。
- **快速过滤条**（顶栏下方贴一条 segmented control）：
  - `进行中 (1)` · `全部 (38)` · `今天` · `本周`
  - 不抢主区空间，贴顶窄条样式（复用现有 `.offline-bar` 风格）。
- **可选**：按"今天 / 昨天 / 本周 / 更早"分组渲染，加分组小标题（淡灰 12px）。
**涉及**：[app.js#L1253 render](file:///Users/admin/Desktop/toDoList/public/js/app.js#L1253)、新增 `sortTodos` 分组逻辑、[style.css 新增分组样式](file:///Users/admin/Desktop/toDoList/public/css/style.css)

### 2. 删除无确认、无撤销、无回收站入口（违背 AGENTS.md 软删除精神）
**现状**：点删除立即软删 + 退场动画 + toast 文案"已移到回收站"。但：
- 代码里**没有 restoreTodo 函数、没有 listDeleted 函数、没有任何回收站 UI 入口**（[db.js](file:///Users/admin/Desktop/toDoList/public/js/db.js) 全文搜不到）
- [toast.js](file:///Users/admin/Desktop/toDoList/public/js/toast.js) 不支持 action 按钮，无法做 "撤销" 5 秒回退
- toast 文案承诺了"回收站"但**用户永远进不去** —— 这是对用户的谎话

**为什么痛**：一指点删无确认 + 不可恢复 = 误删风险高。情侣场景下删错一条（比如对方刚写的心意）容易引发不快。
**建议**（两步走）：
- **临时**（最小改动）：把 toast 文案先改成"已删除（可联系开发者恢复）"，不再撒谎；删除按钮加两段式确认（参考 [img-lightbox 删图](file:///Users/admin/Desktop/toDoList/public/css/style.css#L1839) 已有的 `.img-lightbox__act--confirm` 模式，点一下变深红"再点一次确认"，3 秒还原）。
- **完整**：实现回收站入口（设置/图鉴同位置加一个"回收站"），列出 `deleted_at IS NOT NULL` 的项，支持单项恢复 + 全清；30 天定期物理清理。
**涉及**：[app.js#L790 deleteTodo](file:///Users/admin/Desktop/toDoList/public/js/app.js#L790)、[toast.js 升级支持 action 按钮](file:///Users/admin/Desktop/toDoList/public/js/toast.js)、[db.js 新增 listDeleted/restoreTodo](file:///Users/admin/Desktop/toDoList/public/js/db.js)

### 3. 完成态的复选框完全隐形（opacity:0），用户不知道怎么取消完成
**现状**：[style.css#L596](file:///Users/admin/Desktop/toDoList/public/css/style.css#L596) `.todo--done .todo__check { opacity: 0 }` —— 完成后右上角的复选框视觉上消失，但仍是可点击的透明按钮。"点右上角空白处可取消完成"这个交互**完全无任何视觉提示**。
**为什么痛**：误完成的恢复路径隐藏到用户无法发现；触屏用户要在 18×18px 的盲区里点中。
**建议**：
- 完成态保留一个**极淡的圆形 + 微小对勾**（如 opacity:0.25，rose 100 描边），hover 时 opacity:0.7 —— 既不抢划线文字的视觉，又给"可点回"的暗示。
- 或者更优：完成态把复选框换成"↩ 撤销完成"小按钮（13px 文字+图标），明确语义。
**涉及**：[style.css#L594-L608](file:///Users/admin/Desktop/toDoList/public/css/style.css#L594)

### 4. 长按可触发菜单，但全程无任何 hint
**现状**：长按 350ms 弹 action sheet（[app.js#L1463](file:///Users/admin/Desktop/toDoList/public/js/app.js#L1463)）—— 配图、备注、表情、删除都在里面，但**首次使用没有任何引导**，用户根本不知道可以长按。
**为什么痛**：核心进阶功能（贴图、贴表情、写完成备注）被封印在用户发现不了的入口里——这恰好解释了"38 条 0 张图、0 个表情反应"的零使用率。
**建议**：
- **首次引导**：检测到用户从未长按过时，给第一条未完成 todo 加一个微动效提示（如卡片右侧浮出"长按看更多 ✋"气泡，3 秒淡出，仅显示一次，记 localStorage）。
- **常驻暗示**：todo 卡片右侧加一个极淡的 "⋯" 竖三点图标（opacity:0.25），常驻提示"有更多操作"。
- **加备注/贴表情**这些功能也可在完成时弹的小庆祝 Toast 里加一个 "贴个表情" action 按钮（这又需要 toast 支持 action）。
**涉及**：[app.js showTodoMenu](file:///Users/admin/Desktop/toDoList/public/js/app.js#L1508)、style.css 新增 hint 气泡样式

## 🟡 P1 — 信息架构 / 交互优化

### 5. 空输入静默 return，无反馈
**现状**：[app.js#L382](file:///Users/admin/Desktop/toDoList/public/js/app.js#L382) `if (!text) return;` 直接 return，无 toast。用户点"添加"没反应会困惑。
**建议**：空输入时输入框抖动 + 提示"先写点什么呀"。`toast.error` 即可，3 行代码。

### 6. 取消完成无视觉反馈
**现状**：完成时有粒子+音效+震动+toast；取消完成时**什么都没有**（[app.js#L450](file:///Users/admin/Desktop/toDoList/public/js/app.js#L450) 只在 `nextCompleted=true` 时庆祝）。
**建议**：取消完成时给个轻量反馈——划线渐隐 + toast"已恢复未完成"（极轻量，区别于完成的庆祝）。

### 7. 对方新增/完成无未读高亮
**现状**：对方新增 todo 时，本地只是列表头部多了一条带入场动画的项——但**与本端新建视觉一致**，没有"来自对方"的标记。对方完成时只有 toast 和（克制掉的）光环。
**为什么痛**：长清单滚动 5 屏，新增项淹没在历史里；情侣场景下"对方刚加了什么"是高价值信号。
**建议**：
- 对方新增/完成时给 todo 卡片左侧加一道**淡玫瑰光条**（`box-shadow: inset 3px 0 0 var(--rose-300)`），点击或滚动到该位置后 3 秒淡出。
- 可结合 Realtime：记录"上次查看时间"，未查看的对方新增都保留光条直到滚入视口。

### 8. 无"返回顶部 / 跳到未完成"导航
**现状**：[app.js](file:///Users/admin/Desktop/toDoList/public/js/app.js) 全文搜 `scrollTo/scrollIntoView` 零命中。长清单用户只能手动滚。
**建议**：滚动超过 1.5 屏时，右下角 FAB 上方浮出小按钮"↑ 顶部"或"↗ 未完成 (1)"，点击平滑滚到目标位置。复用 FAB 入场动画风格。

### 9. nudge（轻轻提醒）功能数据库有但 UI 完全没接入
**现状**：[db.js#L155 setNudge](file:///Users/admin/Desktop/toDoList/public/js/db.js#L155) 已实现、`toExternal` 透传 `nudgeBy`、[schema.sql#L58](file:///Users/admin/Desktop/toDoList/supabase/schema.sql#L58) 字段也在——但 **app.js 里 nudge 零命中**，没有触发入口、没有视觉标记、对方收不到提示。
**为什么痛**：nudge 是情侣 App 的核心情感交互之一（"这条我很关注，ta 帮我做好吗"），目前完全是断头路。
**建议**：
- 长按菜单（未完成态）加一项"轻轻提醒"——点击后 todo 卡片右上角浮现一个极小心形角标（淡 rose，带轻微脉动）。
- 对方打开 App 时，nudge_by 不为空且未完成的 todo 顶部加一道光条 + 一次柔和震动（区别于系统通知的强打扰）。
- 一段时间后自动取消（避免长期挂着），或对方完成后自动清。

### 10. 未完成态的长按菜单只有"配图 + 删除"两项，偏空
**现状**：[app.js#L1542](file:///Users/admin/Desktop/toDoList/public/js/app.js#L1542) 已完成才有"备注 + 表情"，未完成只有配图和删除。
**建议**：未完成态补充"轻轻提醒 (#9)"、"加备注预告"（提前写好完成时想留的话），让菜单丰满起来。

## 🟢 P2 — 视觉与细节精修

### 11. 顶栏信息密度过高，窄屏挤
**现状**：爱心 + "在一起 2444 天" + 留言铃 + 图鉴入口 + 头像 —— 在 iPhone 13 (390px) 已经偏挤；窄屏样式（[style.css#L274 max-width:400px](file:///Users/admin/Desktop/toDoList/public/css/style.css#L274)）只缩字号不减持载项。
**建议**：
- "在一起 2444 天" 在窄屏缩为 "2444 天" 单数字+单位（保留爱的计数器分量，去掉"在一起"前缀），节省 ~30px。
- 或把"在一起 X 天"和爱心合并成一个胶囊（爱心 + 数字），整体成为单个可点按钮。

### 12. 主文案 16px 偏小，可考虑 17px
**现状**：`.todo__text { font-size: 16px }` —— 是 iOS HIG 的最低建议值，但中文笔画密，移动端阅读偏紧。
**建议**：主文案 17px / 行高 1.45；meta 维持 12px。差异更明显，主次更清晰。

### 13. 已完成区域整体"灰沉"
**现状**：完成态靠 `text-decoration: line-through` + `color: text-muted` + `shadow-xs`（[style.css#L543](file:///Users/admin/Desktop/toDoList/public/css/style.css#L543)）。37 条全是完成态时，整屏看起来灰扑扑的。
**建议**：
- 完成态背景再淡一档（如 `background: var(--rose-50)` 极淡玫瑰，而非纯白），让"未完成"和"已完成"在色温上有别。
- 配合 P0#1 默认折叠已完成，整屏氛围会立刻清爽。

### 14. FAB 添加面板的"预挂图"按钮发现度低
**现状**：[index.html#L257 attachBtn](file:///Users/admin/Desktop/toDoList/public/index.html#L257) 是个图标按钮在输入框右侧，无任何引导。
**建议**：面板展开时给 attachBtn 一次极轻的"波纹"提示（0.5s 一次淡入淡出的 ring），首次使用时显示，记 localStorage 不再提示。

### 15. 留言入口太隐蔽
**现状**：[index.html#L187 noteBell](file:///Users/admin/Desktop/toDoList/public/index.html#L187) 默认 `hidden`，只在有未读留言时才显示；"写留言"入口藏在纪念日面板里（[#writeNoteBtn](file:///Users/admin/Desktop/toDoList/public/index.html#L114)）。**没未读留言时，整个"心里话"功能从顶栏消失**，用户根本不知道有这功能。
**建议**：noteBell 改成常驻（无未读时是灰色信封图标，有未读时变 rose 脉动）—— 让"留言"功能始终可见，触发"我可以给 ta 写点什么"的联想。

### 16. 列表项删除后无"重排滑入"动画
**现状**：删除时该项 200ms 退场，但下方项**直接跳上来**填补空位（无 transition）。
**建议**：给 `.todo` 加 `transition: transform 0.25s, margin 0.25s`，让下方项平滑上滑填补空位。FLIP 技术或简单 transition 都可。

### 17. 缺少滚动条样式定制
**现状**：iOS 默认滚动条在 WebKit 下不可见，但桌面 Chromium 调试时是系统默认灰色粗条。
**建议**：加 `::-webkit-scrollbar { width: 6px }` + 半透明 rose 滑块，桌面端调试体验更好，移动端无影响。

### 18. 缺少暗色模式
**现状**：[style.css#L83](file:///Users/admin/Desktop/toDoList/public/css/style.css#L83) 主题固定 rose，[theme.js](file:///Users/admin/Desktop/toDoList/public/js/theme.js) 全 no-op；只有留言阅读态有 `.note-read--night` 深色变体。
**为什么痛**：深夜场景（22-5 点）下，整屏 rose 粉在 OLED 屏上偏刺眼——这恰好是情侣互道晚安的高频时段。
**建议**：加 `@media (prefers-color-scheme: dark)` 适配：背景换深玫瑰 `#1c1418`、文字 `#f5e7e8`、卡片表面 `#2a1d22`，主色保留 rose-400（提亮一档）。这是大改，可放 P3。

## ✨ 体验上已经做得很好的地方（继续保持）

> 不是为了表扬而写，而是这些**不能动**——动了反而破坏体验。

1. **设计系统极其扎实**：rose 主色 + 暖灰文字 + 4 档圆角 + 3 级 elevation + 品牌染色阴影，比 90% 的国产 App 都讲究。
2. **心跳动画**：[style.css#L199 heart-beat](file:///Users/admin/Desktop/toDoList/public/css/style.css#L199) 双跳一组的节律仿真心跳，"扑-通"两声后留白呼吸——克制有仪式感。两人同时在线时加速到 `--excited`，是隐藏的情感细节。
3. **完成动画分层**：粒子 + 音效 + 震动 + toast 四重反馈，隐藏款还有 `burstCardRing` 光环——是 App 的"高光时刻"。
4. **空状态情感化**："这里空空的，像在等你" + 大爱心呼吸光晕，不是冷冰冰的"暂无数据"。
5. **离线文案池 51 条诗意短句**：[app.js#L1664](file:///Users/admin/Desktop/toDoList/public/js/app.js#L1664) "风急，信号慢"这种文案让断网也不烦躁。
6. **竞态守卫**：[app.js#L437-L469](file:///Users/admin/Desktop/toDoList/public/js/app.js#L437) `latestIntent` + `beginToggle/endToggle` 双重保护"完成→取消→再完成"乱序——这是真实血泪教训换来的，绝不能动。
7. **留言阅读态按时段换氛围**：晨光 / 星空 / 默认，根据留言写下时间切换背景——是仪式感设计的范本。
8. **骨架屏** shimmer 动画对齐真实卡片尺寸，加载完不跳变。
9. **`prefers-reduced-motion` 全覆盖**：所有动画都有降级，对前庭功能敏感用户友好。

## 🎯 一句话总结

**当前 App 的"视觉与微动效"已经是顶配水准，但"信息架构与交互可发现性"还停留在 demo 阶段——尤其是长清单无组织、删除无撤销、核心功能入口隐藏这三点，把好功能锁在了用户摸不到的地方。先解决 P0 的四条硬伤，体验会上一个台阶。**
