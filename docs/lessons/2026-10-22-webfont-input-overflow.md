# 2026-10-22：web font 撑爆 input 固有宽度，Android 上对钩按钮被挤出屏幕

**关联规则**：铁律二（交付前必须全面测试）/ 铁律三（发布必须让用户拿到）/ 铁律四（代码改动同步更新文档）/ 铁律六（维度 C 正确性）

## 事故

线上 3.7.0（= 霞鹜文楷 web font 落地后的首个版本）发布后，**Android 用户点 FAB 打开添加面板后，
输入框右侧的「对钩」提交按钮和「图片」按钮被整体挤出屏幕右侧**，按钮点不到 → 无法用按钮提交待办
（键盘回车仍可提交，属临时绕行）。**桌面 Chromium（macOS）实测不受影响**；iOS 未实测（按理同走
CoreText 路径、平均字宽与桌面一致，但**没测过的不算已验证**）。

真机取证（V2243A / Android 16 / 1440×3200 @640dpi → **CSS 视口 360px**）：

| 变量 | 值 |
|---|---|
| 添加面板留给输入框的宽度 | `360 − 16×2(padding) − 48(图片按钮) − 48(对钩按钮) − 10×2(gap)` = **212px** |
| 输入框 min-content 地板（霞鹜文楷） | **366px** → 溢出 **154px** |
| 输入框 min-content 地板（3.7.0 之前的系统字体） | 208px → 勉强够用（**余量只有 4px**） |

## 根因（四层叠加）

1. **`.add-panel__input` 是 flex 子项且没写 `min-width: 0`**（`public/css/style.css`）——
   flex 子项的自动最小尺寸 `min-width: auto` = 它的 min-content = `<input>` 的**固有宽度**，
   于是输入框拒绝收缩，`flex: 1` 形同虚设。
2. **`<input>` 没写 `size`**（`public/index.html`）—— HTML 默认 20 字符，
   Blink 按「`size` × 该字体的平均字宽」算固有宽度。
3. **`input { font: inherit }`**（`public/css/style.css`）—— 输入框字体继承 body 的
   `--font-cn`，首选 `"LXGW WenKai"`。
4. **霞鹜文楷的拉丁字符是全角**（≈1em/字符）—— Android WebView(Skia) 算出的平均字宽 ≈16.8px
   → 固有宽 = 20×16.8 + padding/border ≈ **366px**。

366 > 212 → flex 行**向右溢出**，最右边的对钩按钮第一个被挤出屏幕（图片按钮同样出屏）。

**引信是 `81c4080`（PR #134，霞鹜文楷落地，2026-10-14 发布为 3.7.0）**：
它让 `--font-cn` 首选字体在 Android 上**第一次真正生效**，把地板从 208px 抬到 366px。
面板「没有 `min-width: 0`」这个老问题自 v2.7.52/53 建面板起就存在，
一直被「208 vs 212（余量 4px）」这个刀尖平衡掩盖着 —— 字体落地把刀尖换成了炸弹。

## 为什么既有测试体系没拦住（一个盲区 + 一个度量差异）

1. **桌面 Chromium 算出的平均字宽只有 ≈8.35px**（CoreText 路径）→ 固有宽 197px ≤ 212px →
   **不溢出**。所有 Web E2E（`scripts/e2e_common.py` 点 `#addBtn`）、CI required checks、
   每晚 9 个双账号全量回归，**全绿**——绿灯是真的，只是测的是另一个平台。
2. **真机侧是当时唯一没有护栏的一格**：模拟器套件 2026-10-17 已整体移出 CI
   （见 [2026-09-17-device-ci-removal.md](2026-09-17-device-ci-removal.md)），
   而 `81c4080` 自己的发布说明里写着「未验证：Android WebView 真机渲染」—— 漏的正是这一格。

## 修复与防回归

- **修复（1 行 CSS）**：`.add-panel__input { min-width: 0; }` —— 输入框回到 212px，
  两个按钮回到屏内。已用真机 A/B 验证：父提交 `7602f7c`（3.6.x）✓ 在屏内；
  `81c4080`（3.7.0）✗ 出屏 138px；加 `min-width: 0` 后 ✓ 回到屏内。
- **防回归（认知，不是新代码）**：
  1. **flex 容器里的表单控件一律显式 `min-width: 0`** —— 凡是 `flex: 1` 的 `<input>` / `<textarea>`，
     固有宽度是「字体 × 字符数」的函数，换字体就可能换尺寸；`min-width: 0` 是零成本保险。
  2. **字体类改动必须量真机**：web font 落地这类改动影响的是**字形度量**，
     桌面绿灯不代表移动端绿灯（同一份 CSS，两边算出的平均字宽差 2 倍）。
     最低成本验证：真机浏览器打开测试服务器页面，读一次 `getBoundingClientRect()`。
  3. 桌面 E2E 抓不到「平台度量差异」类 bug —— 这类只能靠真机或**构造出同样的度量条件**来测。
