先纠正一件事：已完成区是奖杯柜，不是坟场

你问「是不是没考虑隐藏款的图鉴功能」—— 比这更糟：我上一批四个方案（收起 / 双区归档 / 按天变薄 / 变成数字） 的核心动作全都是让已完成区变轻，而隐藏款的奖励视觉就长在已完成卡片上。用真实数据算一下：

7 / 7

5 / 12

结论：任何「收起 / 变薄 / 搬走」都会把那 7 张渐变卡片一起埋掉 —— 用户再也看不到自己开到过什么， 而图鉴还剩 7 张没解锁，这套系统本来还在驱动「多添一条」。更糟的是我上一批的手机框里一张隐藏款都没放， 所以纸上看着都不错。
这一批的三条约束（对应你说的三句话）：
① 卡片是原子：完成的待办和未完成长得一样，同尺寸同信息，谁都不许缩成一行；
② 往下滑不是问题，问题是滑下去没有收获感 —— 所以给时间加骨架、给完成加痕迹，而不是把内容藏起来；
③ 隐藏款必须留在原位，而且要被看得更清楚。下面每个手机框里都真实带着那 7 张渐变卡。

顺带说一句技术真相：这不是审美问题，是 CSS 优先级问题。我在上一批里写的 .fv-quiet .todo { background: transparent } 优先级高于 .todo--rare， 于是隐藏款的渐变底会被静默吃掉 —— 这正是「改版把图鉴稀释掉」的真实机制。 本页已加了一段稀有度保护（用 !important 重申），并且刻意保留：你可以在第一批的 Quiet / 容器化 里看到隐藏款因此「硌」在版式外面 —— 那就是冲突的样子。

第二批 · 结构（卡片一像素不动）

四版都在回答同一个问题：不隐藏、不缩小、不搬家，怎么让往下滑变得有意义。 全部信息损失为 0，60 件完成的待办都还在原位，尺寸和现在完全一样。 四版里都有那 7 张隐藏款渐变卡，可以顺便确认「图鉴在不在」。

第二批 · 视觉（强化卡片，不削弱）

四版都不改结构、不改卡片尺寸、不改信息，只换「材质」和「痕迹」。 重点看两件事：隐藏款的渐变底有没有被保住，以及完成的卡片是否还和未完成一样有份量 （上一批的 Ⅰ Quiet 和 Ⅳ 容器化会把它压成一行 / 抽掉卡片，这就是它们出局的原因）。

第一批 · 列表显示什么（留档对照）

目标：让打开 App 的第一屏就等于「我接下来要做什么」，而不是「我做过什么」。 四版的分野只有一句话 —— 已完成的那些，是收起、是搬家、是变薄、还是变成数字。 每版下方标注了首屏能看到多少、改动面多大。

问题二 · 视觉语言（四版并排）

现状的视觉问题不在配色（樱粉体系 + 三轨字体是成立的），而在 「每一条都是一个盒子」： 1px 边框 + 投影 + 15/16 内距 + 12 外距 ≈ 80px/条，一屏只能 8 条，而卡片里的信息（7 个字）根本撑不满。 四版按「外壳」的激进程度排序，从去壳到强化壳，都顺手修掉同一个现网缺陷： 完成态把复选框藏成 opacity:0，导致「取消完成」这个操作在视觉上不存在（只能去长按菜单里找「撤销完成」）。
